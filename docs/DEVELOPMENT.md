# Grom Client — redesigned source

Исходники Grom Client (Electron + React + TypeScript) с компактным интерфейсом, настоящим запуском Minecraft через Microsoft-аккаунт и студией скинов.

## Требования

- Node.js 22.12+
- npm 10+
- Учётная запись Microsoft с профилем Minecraft: Java Edition для авторизованной игры и публикации скина в профиль

## Запуск в режиме разработки

```bat
npm install
npm run dev
```

## Сборка Windows

```bat
npm run build
```

Установщик будет в `release`.

## Настройка Microsoft-входа (один раз для сборки)

Microsoft Client ID — публичный идентификатор приложения, а не пароль. Используй собственное приложение; не вставляй в лаунчер client secret, пароль Microsoft или чужой Client ID.

1. Открой [Microsoft Entra admin center](https://entra.microsoft.com/) и создай **App registration**. Для типов аккаунтов выбери вариант, который разрешает личные Microsoft-аккаунты.
2. В **Authentication → Add a platform → Mobile and desktop applications** добавь redirect URI `http://localhost`. Используется внешний браузер и локальный loopback-приёмник, порт назначается автоматически.
3. Скопируй **Application (client) ID** из Overview. В `src/main/microsoftAuth.ts` замени `PASTE_YOUR_MICROSOFT_CLIENT_ID_HERE` на этот GUID. Не добавляй client secret.
4. Пересобери приложение командой `npm run build`.

Вход реализован через authorization code + PKCE и `state`. Пароль вводится на официальной странице Microsoft в системном браузере и не попадает в Grom Client. Microsoft/Xbox/Minecraft-токены остаются в Electron main-процессе; долговременный refresh token сохраняется только через Electron `safeStorage`, если ОС предоставляет защищённый backend. Токены не хранятся в `localStorage` и не передаются интерфейсу React.

**Важно:** Microsoft-вход здесь предназначен для профиля Minecraft Java и запуска игры. Социальные функции Grom (например, аккаунт мессенджера) по-прежнему могут требовать отдельную учётную запись Grom, так как это другая система аккаунтов.

## Студия скинов

В разделе **«Скины»** есть встроенные образы, рисование по текстуре 64×64, палитра, ластик, импорт и экспорт PNG, 3D-предпросмотр и поиск существующего скина по нику на Ely.by. Кнопка «Применить к аккаунту» отправляет текстуру в официальный Minecraft-профиль только после Microsoft-входа; это требует действующего профиля Java Edition. Локально сохранённый PNG сам по себе не меняет скин на серверах.

## Что в проекте

- Компактная главная с обложкой и версиями Vanilla/Fabric; отдельный кинематографичный экран запуска с текущей операцией, этапами и плавным общим прогрессом.
- Обновлённая стартовая заставка длительностью 3 секунды с анимированным брендингом и индикатором активности без фальшивого процента.
- Левая навигация, темы и настройки лаунчера.
- Безрамочное окно с собственными кнопками свернуть / развернуть / закрыть, стилизованными под активную тему; перетаскивание окна доступно за верхнюю полосу.
- Microsoft-вход с PKCE и защищённым хранением refresh token.
- Редактор скинов и 3D-просмотр.
- Остальные обработчики Minecraft, Java/Fabric, сборок, миров, дополнений, профиля и настроек.

## Кастомная верхняя панель окна

Системная рамка окна отключена в Electron. Кнопки управления реализованы через ограниченные IPC-обработчики в главном процессе Electron; renderer не получает прямой доступ к Node.js. На экране входа, загрузки и туториала используется компактная плавающая панель, а в основном лаунчере кнопки интегрированы в верхнюю полосу.

## Экран загрузки

`src/renderer/LaunchExperience.tsx` рисует полноэкранный экран подготовки Minecraft с фоновой сценой, параметрами версии/загрузчика/профиля, текущей операцией и четырьмя стадиями. В `src/main/main.ts` локальные шкалы Java/файлов/подготовки переводятся в монотонный общий прогресс, поэтому индикатор не откатывается назад при переходе между этапами. `Splash.tsx` использует отдельную анимированную заставку длительностью 3 секунды: на отметке 2,5 секунды начинается плавное исчезновение, а затем экран закрывается. Индикатор показывает активность, а не выдуманный процент.

## Проверка сборки

В текущей среде проект не был собран: зависимости npm не удалось установить здесь из-за тайм-аута сети. Для сборки локально используй `pnpm install --frozen-lockfile`, затем `pnpm build`. Добавлен workflow GitHub Actions `.github/workflows/build-windows.yml`, который собирает Windows-инсталлятор и публикует его как артефакт. В этой среде полная сборка не завершилась из-за тайм-аута установки зависимостей; после CI всё равно проверь вход Microsoft-аккаунтом, у которого есть Minecraft: Java Edition.


## Grom Client 1.3.1 — обслуживание и локальные моды

- Вкладка «Дополнения → Моды»: перетаскивание локальных `.jar` в папку `mods` основной игры или выбранной сборки. Проверяются расширение, размер, пустые файлы и дубликаты.
- Статистика запусков: количество запусков и суммарная длительность для запусков, записанных после установки этой версии.
- Диагностика логов: эвристический поиск типичных причин в `latest.log` и crash reports. Это подсказки, а не гарантированный диагноз.
- Проверка модов: SHA-256 и простые предупреждения по имени/размеру. Это не антивирус и не гарантирует безопасность JAR-файла.
- Проверка и восстановление Minecraft: сверяет клиент, библиотеки, asset index и ассеты выбранной версии; отсутствующие или повреждённые файлы загружает заново.

Сборка требует Node.js и зависимостей из `package.json`.


## Обновление 1.3.5

- Исправлена причина вылета Minecraft 26.3 `Incompatible Java and native library versions`: DLL больше не собираются сканированием всей общей папки `libraries`. Лаунчер использует только natives, объявленные в JSON именно запущенной версии, очищает папку natives перед распаковкой и пишет список выбранных native JAR в debug-лог.
- При подготовке версии скачиваются её библиотечные артефакты и подходящие для Windows native-классификаторы; classifier-only библиотеки больше не принимаются за обычные JAR в classpath.
- Java выбирается по `javaVersion` из метаданных Mojang; при выборе версии в интерфейсе отсутствующий runtime начинает устанавливаться автоматически, а перед запуском повторно проверяется точное совпадение major-версии. Поддерживаются Java 8 для Alpha/Beta и новые Java для современных версий.
- Исправлен анализ номера Java 8 (`1.8.0_xxx` правильно определяется как Java 8).
- Для старых версий без `assetIndex` установка не падает на проверке ресурсов; параметры запуска берутся из `minecraftArguments`, а при их отсутствии используется legacy-формат.
- Иконка в «О программе» центрируется отдельной flex-обёрткой, независимо от размеров контейнера.

## Обновление 1.3.2

- При каждом запуске выполняется сверка клиентского JAR, библиотек, asset index и ресурсов Minecraft с SHA-1/размером из метаданных Mojang. Отсутствующие, обрезанные или повреждённые файлы скачиваются заново во временный файл и заменяются только после проверки.
- Проверяются ответы HTTP и перенаправления, добавлены повторы скачивания и очистка незавершённых файлов.
- Старые версии, для которых метаданные указывают `virtual` или `map_to_resources`, получают необходимые зеркальные файлы ассетов.
- Лаунчер не считает запуск успешным, если Java не смогла стартовать или Minecraft завершился в первые 1,8 секунды. Ошибки сохраняются в `.gromclient/logs/launcher-debug.log`.
- Полностью обновлены экран входа/регистрации, модальное окно профиля и общая визуальная система лаунчера. Логика Microsoft-входа и Grom-регистрации сохранена.

Проверка сборки: `npm run build`. В среде разработки зависимости должны быть установлены из `pnpm-lock.yaml` (предпочтительно `pnpm install --frozen-lockfile`).

### Офлайн-профиль и Minecraft 1.16.5

В Minecraft Java 1.16.5 есть известное поведение: при использовании offline-профиля кнопка сетевой игры может оставаться неактивной, хотя в более новых версиях она доступна. Это поведение конкретной версии игры, не переключение профиля самим Grom Client. Офлайн-профиль не содержит официально подтверждённой игровой сессии; лаунчер не подменяет серверы авторизации и не отключает проверки доступа. Для официального сетевого режима используйте официальный вход Minecraft/Microsoft с разрешённым мультиплеером.
